# 调研手册：源、口径、证据

传记的可信度由三件事决定：**找到对的源、对齐口径、把不确定说清楚**。

## 一、三源矩阵

| 源 | 能回答什么 | 典型入口 | 口径与坑 |
|---|---|---|---|
| 官网更新日志 / 公告 | 版本日期、改了什么、官方定性 | 官网 `news/update`、`news/official` | 国服与国际服常差 1 天（时区）；「公告日」≠「生效日」 |
| 官方 FAQ / 收费说明 | 买断转免、补偿、平台政策 | 官网 FAQ、商店页 | 补偿口径要写「按原价/按实付」，两者差很多 |
| 财报 / 投资者材料 | 销量里程碑、收入定性、端手游结构 | NetEase/腾讯 IR、业绩稿 | 很少拆单产品；「收入增加来自某产品」是定性，不是流水数字 |
| SteamDB / SteamCharts / CSGODT | Steam 同时在线（CCU）月峰值/均值 | steamdb.info、steamcharts | **只含 Steam**，不含官服、Epic、主机；峰值是瞬时，不是 DAU |
| 小黑盒 | 含官服的全平台在线趋势 | 小黑盒 App/网页 | 口径不透明，常被当「全平台」；适合看趋势与拐点，不宜当精确值 |
| 七麦 / 点点 / Sensor Tower | 手游流水与榜单排名（估算） | 七麦、点点数据 | 全部是估算；只能写「约/估算」，并与官方财报交叉 |
| Steam 评测 / TapTap | 口碑、差评主题、评分 | Steam 商店页、TapTap | 「总好评率」与「最近评测」要分开；差评潮会短期拉低 |
| 贴吧 / NGA / 小黑盒 / B站 / 抖音 | 舆论事件、玩家语言、出圈程度 | 站内搜索、热帖 | 幸存者偏差；高播放≠高留存；引用要标「玩家观点」 |
| 赛事页 / Liquipedia | 电竞投入、奖金、赛区、成绩 | 官方赛事页、liquipedia | 奖金是总池还是冠军奖金，要写清 |
| 网吧热力榜 | 线下网吧热度 | 顺网/网吧榜单 | 只覆盖网吧场景，不能代表全量 |

> 原则：**官方口径讲事实，平台口径讲趋势，社区口径讲感受**。三者不许混成一句话。

## 二、检索词包

按阶段换词，别用同一个 query 搜到底。

| 目标 | 中文词 | 英文词 |
|---|---|---|
| 上线与首月 | `上线 时间 公测 开服 销量 首周 首月` | `launch date, copies sold, first week` |
| 销量/玩家里程碑 | `销量 破 万 份 玩家 突破 万` | `million copies, registered players` |
| 收费模式变化 | `买断 转 免费 补偿 老玩家 退款` | `free to play, compensation, refund` |
| 在线/流失 | `在线 人数 峰值 跌破 流失 Steam` | `concurrent players, player count drop` |
| 版本与内容 | `新地图 新英雄 新玩法 赛季 大版本` | `new map, new hero, season` |
| 竞品冲击 | `竞品 分流 上线 冲击 主播 转型` | `competitor, player migration` |
| 舆论/事故 | `差评 外挂 误封 平衡 匹配 氪金 退坑` | `review bomb, cheat, ban wave, balance` |
| 电竞 | `职业联赛 世界冠军赛 奖金 亚运` | `esports, world championship, Asian Games` |
| 财报 | `财报 收入 端游 手游 增长` | `earnings, revenue, PC games` |

检索技巧：

- 先搜「产品名 + 关键词」，命中后再加 `site:` 限定到官网/Steam/小黑盒。
- 时间敏感话题加 `recency:30`；历史事件加年份，不要靠「最新」。
- 一次只回答一个问题；同一 query 不重复搜，换同义词再试一次即可。
- 看到「XX 亿流水」「在线破 X 万」先找原始出处；找不到就降为 C 级或不用。

## 三、口径对照（写作前先对齐）

| 容易混 | 正确写法 |
|---|---|
| Steam 峰值 vs 全平台在线 | 「Steam 同时在线峰值 26.4 万〔E5〕；小黑盒全平台口径峰值为 38.5 万〔E6〕」 |
| 月峰值 vs 日均 | 「2026 年 9 月 Steam 日均 2.5 万、峰值 7.3 万」 |
| 销量 vs 玩家数 | 买断期写销量；转免后写「累计玩家/注册用户」，不写「又卖了」 |
| 官方收入 vs 估算流水 | 财报写「端游净收入增加」，第三方写「估算流水约 X 亿」 |
| 总好评率 vs 近期好评 | 「简体中文总评 71% 多半好评；最近 30 天 59% 褒贬不一」 |
| 赛事总奖金 vs 冠军奖金 | 两个数都写，标明是哪一个 |

## 四、证据分级与编号

| 级 | 类型 | 例 |
|---|---|---|
| A | 一手官方 | 官网公告/FAQ、财报、官方赛事页、商店页定价 |
| B | 官方二手/权威平台 | 官方访谈、新华社/财经媒体、SteamDB/小黑盒原始数据页 |
| C | 第三方与社区 | 媒体复盘、UP 主视频、贴吧/NGA 帖、估算榜单 |

- 关键结论（转免、峰值、流水拐点）至少 1 条 A 或 2 条独立 B。
- 全篇统一 `E1…En`，首次出现登记进第 7 段证据表：`ID | 内容 | 来源（短标签超链接）| 时间 | 等级`。
- 正文引用写 `〔E3〕`；需要原话时用短引文，不改写原意。
- 来源列用短标签（「官网 7·14 公告」），不贴整条 URL。

## 五、时间与真实性校验

- 发布时间早于上线日 → 只能是预生成/前瞻，规则细节不采信。
- 发布时间早于所引版本 → 不能描述当前版本。
- 标题含「预测/前瞻/爆料/或将」→ 最高 C 级。
- 停运/停更后的通稿，不能证明停运前的数据。
- 同一作者批量产出的「深度解析」互相抄同一段 → 整体降级。
- 校验锚点：官方上线公告、版本公告日期、财报季度。

## 六、冲突与推断

冲突不要沉默处理：

1. 第 1 段或第 4 段写清采用哪套口径；
2. 第 7 段「口径冲突」列：谁说什么、等级、为什么采信另一条；
3. 优先级：官方公告 > 官方页面 > 平台原始数据 > 权威媒体 > 社区。
4. 最高级证据与低级证据冲突时，低级那条是「错误信息」，不是「另一种说法」。

推断格式：`〔推断，依据：E5/E7，置信度：中〕结论`。只从已记录事实推导，不用「业内通常」。

## 七、省 token 的检索预算

- 每个节点 3–5 个 query，摘要 300–600 token；命中后再抓 1–2 页。
- 抓页用 `snippet` 定向取「日期 + 数字 + 官方原话」，不整页复读。
- 先建年表再补证据，避免边搜边写导致的重复检索。
- 一条证据只登记一次；后续引用编号，不重复贴链接。
- 图表数据直接从已登记证据里抄，不二次搜索。
