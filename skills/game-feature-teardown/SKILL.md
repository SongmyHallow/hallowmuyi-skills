# 游戏功能拆解

把“一个功能”拆成可复用的设计知识。成品是**暗色 HTML 报告**（含浅色切换），配实机截图与图表；要进知识库时再同步飞书云文档。

## 任务形态

| 形态 | 信号 | 做法 |
|---|---|---|
| 单功能深拆（默认） | 一个游戏 + 一个功能 | 走完整流程 |
| 整系统拆解 | 大系统（如“养成系统”） | 拆子系统清单，逐个跑，加总章 |
| 跨产品对比 | 多游戏同一类功能 | 以差异矩阵为主，不必每款写全篇 |
| 快速扫描 | 只要结论、时间紧 | 本体 + 分布 + 3 条启示，标“扫描版” |

## 报告结构（顺序固定）

1. **功能本体**：定义与口径、系统位置图、入口、界面、流程、规则数值、版本变更。
2. **产品分布**：先查同源机制，再查同设计目的的其他解法；两层分开写，形似但问题不同的不入表。
3. **设计目的**：官方原话优先，其次媒体，最后推断。
4. **本土化魔改**：只对同源/同目的产品逐个讲改了什么、为什么改，落到受众、付费模型、生态。
5. **方法论**：适用产品类型、可调参数、市面方案对比、优化空间、验证方式。
6. **证据与存疑**：证据表（编号/内容/可点击链接/时间/等级）、口径冲突、存疑点、全部来源链接。

结论只放导语三行内，不替代上述顺序。

## 流程

1. **锁定对象**：游戏、版本、平台、拆哪块、拆解目的；缺关键信息问一句，能默认先默认并写假设。
2. **口径消歧**：同名功能常分多层（身份/匹配/称号/玩法）。搜 2–3 个来源列定义，优先官方公告 > 官方页 > 媒体深度稿 > 攻略 > 创作者解读；采用哪层写进导语，冲突进第 6 节。
3. **同源检索**：把功能拆成 3–5 个可判定特征，逐产品核对“有没有做过同一套东西”，核过的产品都要留记录。查不到再找同设计目的的其他解法；形似但问题不同的剔除，一句话说明为何不纳入（例：双人协作解决社交，不是“高手往哪去”）。
4. **采证编号**：搜索、抓页、读图并用，用户给的截图优先。每条编 `E1…En`，记来源、时间、版本，按 `references/evidence-and-sourcing.md` 定级；发布早于开服/所引版本的按预生成降级；截图下载到本地 `assets/`。
5. **搭骨架**：`python3 scripts/scaffold_report.py --game X --feature Y --competitors A,B --out X_Y_拆解.md`。
6. **填事实**：按 `references/teardown-dimensions.md` 逐维回答，只写可验证内容，答不上标 `〔待验证〕`。
7. **做意图**：每个设计追问解决什么、代价是什么、有无更优解；写表并标置信度，推断指回事实。
8. **做对比**：差异矩阵 + 取舍解释，解释落到受众结构、付费模型、代练生态，不判简单优劣。
9. **出图**：数据类优先图形化（阶梯/区间/占比/流程/关系）；每图标题写结论、图注标口径与证据；无可信数据不画示意数据图。截图 2–5 张，用 `<figure>` + `<figcaption>`（含证据编号）。
10. **生成 HTML**：`python3 scripts/build_html.py <md> --title "…" --subtitle "…" --meta "品类;版本;日期;N 条证据" --out <html>`。自动给出侧边栏目录（锚定 + 高亮跟随）、暗/浅主题开关（含视觉块与图表双版本）、强调色。
11. **自检与交付**：`python3 scripts/check_report.py <md>` 无错再交；默认交 HTML。要进飞书时读 `lark-doc/SKILL.md`：原生标题表格 + `<img path="@./assets/x.jpg"/>` + 关键视觉 `<html5-block>`（`build_html.py --block`，≤500KB，禁 base64）。
12. **归档入库**（默认执行，除非用户说不入库）：按 `references/lark-intake.md`——文档迁入 `game-library/<产品>/03_素材与参考`，并在「游戏资料索引」加一行；加行前先查同产品最新版本，报告版本落后要标注。

## 原则

- 先结构后评价：讲清“是什么、怎么转”，再谈“好不好”。
- 结论可回溯：事实带 `〔E1〕`，推断写 `〔推断，依据：…〕` + 置信度；禁“显然”“业内通常”。
- 不编数字：只有区间写区间，只有体感写体感，算出来的写推导。
- 图服务结论：不做装饰配图；对比只比同源或同目的。
- 承认边界：后台逻辑、真实流水、内部指标标“未知”。

## 自检

- [ ] 本体写清入口/界面/流程/规则/数值，没玩过也看得懂
- [ ] 系统位置图存在，且位置 ≠ 流程图
- [ ] 产品分布分“同源/同目的”两层，无关机制已剔除并说明
- [ ] 设计目的有官方原话或 A/B 级证据
- [ ] 魔改解释落到受众与生态，不是罗列改动
- [ ] 推断有依据与置信度；截图 ≥2 张带图注
- [ ] 证据表链接可点、时间齐全；`check_report.py` 通过
